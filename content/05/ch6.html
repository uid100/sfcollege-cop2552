Static Class Members

This chapter begins with the static keyword for class members and what this means. You learned previously that when the keyword static is applied to a variable or method, this entity belongs to the class, not the object, or a particular instance of the class.

 

Static variables and methods are defined and have one memory location that may be accessed by any> object of that class.

 

If a variable is declared as static and given an initial value, the initialization of that variable only happens once. For example:

private static String CoName = "Best Development Company";

 

When the program initially executes, the variable CoName is initially defined as "Best Development Company" and will not initialize again, regardless of the number of objects instantiated.

Program 6-1 in the textbook shows a similar use of static variables and how to increment and use a static variable throughout the program.

 

If a method is declared as static, it is independent of the object instances. For example, if a program was calculating weight and the user entered the number of tons and wanted the exact value in pounds, a static method would be appropriate.

private static double tonsToPounds(double numTons)
{
    return numTons * 2000;
}

This method may be called when the user enters the number of tons. It may be called from any object instantiated from the class.

 

Another example:

private static void displayName()
{
    System.out.println("Best Development Company");
    System.out.println("All of your development needs resolved!");
}

This method may be called from any object that needs to display the company title and slogan on each printout of information.

Program 6-3 in the textbook is a good example that demonstrates the use of static methods and how to call and use them appropriately.

 

Overloaded Methods

As we progress through the last two components of object-oriented programming - inheritance and polymorphism - you will likely see and use overloaded methods.

Put simply, an overloaded method is a method that has the same name as another method. However, something must differ. Either the return type is different and/or the data types and/or the number of parameters differ.

Overloaded methods are used often. Especially if something of a similar nature is needed, but perhaps different data types will be used. For example, to calculate area, you may want to square an input number, you may write a method to calculate the area of different spheres. Perhaps you want to find the area of a circle and the area of a triangle. The calculations for each sphere is different, but you can use overloaded methods:

//calculate and return the area of a circle
private static double getArea(double radius)
{
        return radius * 3.14159;
}

//calculate and return the area of a triangle
private static double getArea(double height, double base)
{
        return ((height * base) * .5);
}

You'll notice that the two methods above have the same return type and the same method name. The difference here is that when calculating the area of a circle, only one parameter is passed. To calculate the area of a triangle, two parameters are passed. This is how the system will know which method to execute when called; by the number of parameters and the corresponding data types in the parameter list.

This is called the method signature.

  • getArea(double)
  • getArea(double,double)

 

Although the two methods have the same name, their signatures are different and execution is not ambiguous.
