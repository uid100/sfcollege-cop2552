Exceptions

You have learned to handle exceptions in C++ and C#.  At this point, you should understand exceptions and why you - the developer - must capture them.  If not, the system throws an exception that the user will see which is considered taboo and is a sign of bad programming.   The user should not ever see a system thrown exception!

Fortunately - and I'm sure it comes as no surprise - exceptions in Java work as they do in C++ and C#.

A Review

Exceptions in programming are not usual occurrences.  An exception is any error condition or unexpected behavior in an executing program.  The programs you write can generate many types of potential exceptions, such as (but not limited to) when:
  • your program asks for user input, but the user enters invalid data
  • the program attempts to divide a value by zero
  • you attempt to access an array with a subscript that is too large or too small
  • you calculate a value that is too large for the answer's variable type.
The object-oriented techniques to manage such errors comprise the group of methods known as exception handling.

Traditionally, programs that would run into trouble would terminate the program.

In object-oriented terminology, an exception is a message (an object) that is passed from the place where a problem occurs to another place that will handle the problem.  Exception handling acknowledges inheritance and can be overridden by the programmer.

Using Try Blocks

The call to the potentially offending function should be placed within a try block.  A try block consists of one or more statements that the program attempts to execute, but that might result in thrown exceptions.

A try block includes the following components:

  • the keyword try
  • an opening curly brace
  • statements that might cause exceptions
  • a closing curly brace


Catching Exceptions

To handle a thrown object, you include one or more catch blocks in your program immediately following a try block.  A catch block includes the following components:
  • the keyword catch
  • an opening parenthesis
  • the exception type
  • a name for the instance of the exception type
  • a closing parenthesis
  • an opening curly brace
  • statements that take the action you want to use to deal with the error condition
  • a closing curly brace
As with the try block, a catch block must contain curly braces, even if they contain only one statement.
 
 
try
{
       // statements that might cause an Exception
}
catch ( Exception e )
{
       // do something about it
}
// Statements here execute even if there is no Exception

If you want a catch block to execute, it must catch the correct type of argument thrown from a try block.  If an argument is thrown and no catch block has a matching argument type, then the program terminates.

You cannot include a catch block within a program unless you have a try block.

 Advanced File I/O

We have worked with sequential access files and are aware of their strengths and weaknesses.  Sequential access files are inappropriate for instant-access applications in which a particular record of information must be located immediately.

Common instant-access applications are used everyday.  Airline reservation systems, registration at our college, banking systems, ATMs and other kinds of transaction processing systems that require rapid access to specific data use instant access to files.  The bank at which you have your account may have thousands of customers, yet when you use an ATM, your account is checked for insufficient funds in seconds.  This type of transaction processing can only be accomplished using random access files.  Imagine sorting through a sequential access file to obtain your account information!

Use random file access when you must instruct the program to go directly to your record.  The simplest way to create random access files is to make all the records in the file the same length.  Using fixed-length records makes it easy for a program to calculate the exact location of any record relative to the beginning of the file.  A fixed-length record file contains records that are all the same length.  That is, each record takes the same amount of space.

Data can be inserted in a random-access file without destroying other data in the file.  Data stored previously also can be updated or deleted without rewriting the entire file.

Creating and Writing to a Random-Access File

As with sequential files, you must open random-access files before reading or writing to them.  You can use any of the read access modes if you are only going to read a file randomly. 

To create a random-access file you would use the RandomAccessFile class:

                    RandomAccessFile randFile = new RandomAccessFile("random.dat", "r");

The access modes are "r" for reading and "rw" for reading and writing.

Things to remember:

  • if you open a file in "r" mode and the file does not exist, a FileNotFoundException is thrown.
  • if you open a file in "r" mode and attempt to write to it, an IOException is thrown.
  • if you open an existing file in "rw" mode, it will not be deleted.  The new data will be appended to the end of the current contents of the file.
  • if you open a file in "rw" mode and the file does not exist, it will be created.

Reading From a Binary File

To work correctly, a program that reads data from a binary file must use the same structure as the program that created the file.  That means the data to be read must be read in the same format as the program that wrote the file.

Reading data back from the file requires the use of the read( ) function which takes the same arguments as the write( ) function.  Again, the address of the variable must be specifically cast to be a pointer to char.
 

#include <fstream>
#include <iostream>
#include <string>
using namespace std;

class Data
{
public:
    void Display();
private:
    string first;
    string last;
    int age;
    float salary;
};

void Data::Display( )
{
    cout << endl << first << " " << last << endl
           << "aged: " << age << endl
           << "salary: " << salary << endl;
}

int main( )
{
      Data employee;

      ifstream employ("c:\\c++\\random1.dat", ios::binary);

     if ( !employ )
      {
          cout << "Could not open input file" << endl;
          return 1;
      }

     employ.read((char*) &employee, sizeof(employee));      // priming read

     while ( employ )
      {
           employee.Display( );
           employ.read((char*) &employee, sizeof(employee));
      }
     return 0;
}
 

Unformatted I/O with read, gcount and write

To date, we've read and written our data as simply input or output of raw data.

For example, if a program had the statement:

                cout.write("This is a cool program", 20);

what would display would be:        This is a cool progr

which simply displays the first 20 characters of the string.

However, the read member function can input a designated number of characters into a string or character array.  If fewer than the designated number of characters are read, the failbit is set.

For example, if a program had the statement:

                cin.read( name,  20);

and the user typed in:  Chubby Checkers

only 15 characters will be read in, so the designated number of characters (20) were not read in so the failbit is set.  Member function gcount( ) will report the number of characters read by the last input operation.

If the end of file is reached before num characters have been read, then read( ) simply stops, and the buffer will contain as many characters as were available.  You can find out how many characters have been read using  gcount( ), which has the prototype:

               int gcount( );

gcount( ) returns the number of characters read by the last input operation.  To use this:

                char buffer[ 80 ];
                cout << "Enter a sentence: ";
                cin.read( buffer, 20 );                // "This is a cool program" was entered
                cout << endl << "The sentence entered was: " << buffer << endl;
                cout.write( buffer, cin.gcount( ) );
 
 

Finding a Specific Record in the File

The advantage of using random access files is that you can go directly to the record that you would like to display or process.  However, in order to do this, you must instruct your program to go directly to your record.

A fixed-length record file contains records that are all the same length.  That is, each record takes the same amount of space.

As with sequential access files, you must open random access files before reading or writing to them.  You can use any of the read access modes ( pg. 763  in your textbook ) if you are only going to read a file randomly.  To update a file, you should use the fstream stream.  To update a record you would:

        fstream employ("c:\\c++\\random1.dat", ios::binary | ios::in | ios::out );

As always, remember, you can't open a read-only file for output!

Each file object has two integer values associated with it.  These are called:

        1.  get pointer - specifies where in the file the next input operation will occur
        2.  put pointer - specifies where in the file the next output operation will occur.

These values signify the location, specified in bytes, where reading or writing will occur.  ( Note:  the term pointer in this context does not refer to the normal C++ pointers used as address variables.)  Each time an input or an output operation takes place, the appropriate pointer is automatically advanced.

What are they used for?  The default actions allow an existing file to be read from the beginning continuing to the end.  When writing to a file, the default action deletes any existing contents and starts writing from the beginning.  However, if the file is opened with the ios::app flag, the existing contents will not be deleted and writing to the file will start at the end.

There will be times when you will want to control the file pointers so that they can read from and write to any location in the file.  The seekg( ) and tellg( ) functions allow the programmer to set and examine the get pointer, and the seekp( ) and tellp( ) functions do the same for the put pointer.

The seekg( ) function can be used in two ways.  The first is where a single argument represents a position in the file.  The start of the file is byte 0.

The second is using the seekg( ) with two arguments.  The first argument represents an offset from a specific location in the file, and the second stipulates the location from where the offset is measured.  There are three possibilities for the second argument,

            ios::beg    is the beginning of the file
            ios::cur    is the current pointer position
            ios::end    is the end of the file

The seekg( ) function moves the associated file's current get pointer offset number of bytes from the specified origin.  The seekp( ) function moves the associated file's current put pointer offset number of bytes from the specified origin.

Generally, random access I / O should be performed only on those files opened for binary operations.  The character translations that may occur on text files could cause a position request to be out of sync with the actual contents of the file.

For example:

            seekp( -20, ios::end );

will set the put pointer to 20 bytes before the end of the file.

            seekg( 20, ios::beg );

will set the get pointer to 20 bytes after the beginning of the file.

            seekg( 50, ios::cur );

will set the get pointer to 50 bytes after the current pointer position

            seekp( -50, ios::cur );

will set the put pointer to 50 bytes before the current pointer position.
 

tellg( ) returns the current get location.
tellp( ) returns the current put location.
 

#include <fstream>
#include <iostream>
#include <string>
using namespace std;

class Data
{
public:
     void Display( );
private:
     string first;
     string last;
     int age;
     float salary;
};

void Data::Display( )
{
      cout << endl << first << " " << last << endl
           << "aged: " << age << endl
           << "salary: " << salary << endl;
}

int main( )
{
      Data employee;
      int number;

      ifstream employ("c:\\c++ temp\\random1.dat", ios::binary);

      if (!employ)
      {
          cout << "could not open input file" << endl;
          return 1;
      }

      employ.seekg( 0, ios::end );           // position pointer to end of file

      int endOffile = employ.tellg( );       // return pointer position
                                                            // this is the length of the file
                                                            // in bytes.

      int noOfrec = endOffile / sizeof(employee);     // how many records in the file

      cout << "There are " << noOfrec << " in the file" << endl;
      cout << "Enter a person #: ";
      cin >> number;

      int position = ( number - 1 ) * sizeof(employee); // position at specified
                                                                                              // person

      employ.seekg(position);

      employ.read((char *) &employee, sizeof(employee));

      employee.Display( );

      return 0;
}
