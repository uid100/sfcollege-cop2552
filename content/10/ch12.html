Chapter 12 JavaFX: Advanced Controls

 

In the last chapter, we read about placing objects on the display. Next, we'll expand that to include styling, common user controls, and approaches to debugging GUI applications.

As you've learned, one of Java's greatest strengths is cross-platform support. There is wide support for the Java run-time which, at least in theory, supports the concept of write-once, run-anywhere. As systems development has advanced, user's expectations have changed. Graphical User Interfaces or GUIs are ubiquitous. We take them for granted. Users have an expectation of how functional elements work. They don't need to taught that a that radio button selectors are round and only one in a group may be selected at a time. Input text box sizes should give hints to what an application is expecting for user inputs, menu selections may be selectable with check-marks, or may cause application behavior change.

If you stop and think about it, the GUI design, at-a-glance, and leveraging common behaviors, not only improves product acceptance, but also greatly reduces or even eliminates the need for user training in most cases.

 

Styling with CSS

In addition to usability, part of User Experience (UX) design is concerned with product acceptance and even brand recognition.

It is not uncommon that products are launched using web applications in the interest of cross-platform support and greater style and design control. It may be easier to maintain a single product base without having to consider the many different hardware and operating system platforms that might be accessing it.

This chapter opens up with a discussion about applying CSS styling to the objects and controls placed on the interface. This is the same Cascading Style-Sheets that you've used in web application design and development.

This opens up possibilities for writing standalone applications to meet many of the same requirements and objectives that are traditionally left to web applications, without being tethered to a remote server.

Read through the examples. Try them. If you have access to multiple system operating systems, consider testing them across those platforms. Do they look the same?

Approaches to Debugging

The Eclipse IDE does provide a useful debugging environment, and allows the developer to set breakpoints to step through the code and view the values of different pieces as execution progresses. When you started coding, it was usually pretty simple to just insert a few print() statements throughout your code and watch how the values changed from step to step.

This approach has a couple of challenges in a GUI application. First, a console window may not be visible during 'normal' operation, and second, the nature of the object approach and user event handler model means that processing sequence may not be a step-by-step, linear process.

Think about these challenges as you read through the chapter. Do the ideas overcome these challenges with debugging a GUI-based application?

One approach that I've used for many (many!) years is to define a global static constant near the entry point of my applications to enable simple debugging while I'm developing. In Java, this might look like this:

public static boolean DIAGNOSTIC = true;

 

Then, in the code where I want to see the progress or value of a variable,

if(App.DIAGNOSTIC) System.out.printf("myMethod(%d)",argValue);

 

Now if I want to turn all of my diagnostic messages on or off for testing, it's very simple to change only one flag. Also, deleting all of these before final production test, is a simple matter of searching for all of the instances of "DIAGNOSTIC" and deleting those lines.
